## Decisions
- **Stack is §2 option A**, as the spec chose: no build step, no dependencies, pdfmake 0.3.11 vendored.
- **Delivery is `pr`, Sprint 1, base `develop`.** Spec §2 says pushes to `main` go to production, and §9 step 9 says "merge to `main` to deploy". With `main` as the base, every unit merge would publish a half-built tool. Units therefore merge into `develop` (Vercel preview); release is one `develop → main` merge after §10 passes. This matches `court-booking-system`. The user must create `develop` from `main` first; the code is identical, so this plan is valid for it.
- **Banned wording:** "official receipt" and the other banned phrases may appear only inside the approved disclaimer sentences, which live in `public/js/copy.js`. `tests/wording.test.js` removes those exact sentences, then scans `public/` (except `vendor/`), case-insensitively, for the banned phrases. The user chose this.
- **Donation:** a `support.html` page shows the owner's GCash/Maya QR from `public/img/donate-qr.png`, linked from the footer. **The user supplies that image** before prompt 19 runs.
- **Profile:** prompt 01 writes `CLAUDE.md` with the spec's four rules, plus the workflow profile headings (Project, Workflow, Commands, Review constraints, High-stakes paths, Hidden coupling), so audit and build can rely on it. `Jira key:` is filled in at the ticket step.
- **Spec addendum:** prompt 01 appends "§11 Implementation decisions" to `docs/SPEC.md`, recording every deviation below, so the spec remains the single source of truth.
- **Document shape additions** (version stays 1; nothing has shipped):
  - `withholding_preset`: a preset id or `"custom"`. Two presets share 5% and 10%, and the 5% helper text depends on the preset.
  - Label key `ship_to_title` ("Ship To"), from invoice-generator.com's API. The spec's list omits it, but the Ship To region needs a label.
  - `fields.discounts` and `fields.tax` follow invoice-generator.com: `false` is off, `"%"` is a percentage, `true` is flat.
- **Numbers in state:** state holds canonical `.`-decimal strings only. An entry that fails to parse is kept in the editor's in-memory `invalid` map (path → raw text and error code). It is never saved; its state value becomes `""` (calculated as 0), and validation reports it. This closes the de-DE trap where `1.500` (meant as 1,500) would be stored and re-read as 1.5.
- **Flat money inputs** (flat discount, flat tax, shipping, amount paid) accept up to 4 decimals, and `calc.js` rounds them half up to the currency's places. Switching currencies therefore re-rounds instead of raising errors (§4, "typed values untouched").
- **Discount %** accepts up to 3 decimals, like tax and withholding rates.
- **Rounding for negative intermediates** (only reachable with invalid input that validation blocks) is half away from zero.
- **Paper default** comes from the browser language when a document is created: Letter for en-US, en-CA, en-PH and es-MX, A4 otherwise (§6).
- **PDF filename** puts the title in title case: `BILLING STATEMENT` and `BS-0007` give `Billing Statement BS-0007.pdf` (§6 example).
- **QR "never scaled up":** `main.js` reads the image's natural size at download time and passes it in; `buildDocDefinition` scales by `min(1, 120/w, 120/h)` (px→pt at 0.75).
- **History CSV:** UTF-8 with a BOM and CRLF line endings. Text cells that start with `= + - @`, a tab or CR are prefixed with `'` to block formula injection. Amounts are plain canonical decimals.
- **Editor render model:** full re-render only on structural changes (mode, add or remove a row, toggles, currency, format, import or new document), restoring focus by `data-path`. Every `input` event updates state and then only the computed cells and totals, via `textContent`.
- **Image checks:** `state.js` exports `checkImageDataUrl()` (PNG or JPEG prefix, magic bytes, decoded size ≤ 500 KB), used by both upload and import.

**Audit 2026-10-29 mitigations** (see [[2026-10-29-invoice-v1.audit]]):
- **Browser floor** is Firefox 98+ (the spec's `<dialog>` needs it), recorded in SPEC §11 (F4).
- **Edit binding:** `check` binds booleans; typed toggles use `data-action` buttons with explicit values; the form cancels `submit` because of CSP `form-action 'none'` (F5, F14).
- **`setLabel` default** for `header` is the mode's title (F6). The PDF items loop keeps the original index (F7).
- **History numbers** are cached in `app.historyNumbers`, so storage is never read per keystroke (F3).
- **New document** keeps the last-used currency when no default is saved (F8). Plain spaces and apostrophes count as thousands separators (F9).
- The **not-saving banner** is verified with site data blocked, not a private window (F10).
- **Owner precondition before IG-1's PR (F11):** connect the GitHub repo to Vercel with production branch `main`, then turn off Deployment Protection for previews or create a Protection Bypass for Automation secret. Preview header checks send it as `x-vercel-protection-bypass`; never print it.
- **Verification commands** use `find … | xargs node --check` and `! grep -q` so a correct run exits 0 (F1, F2). `donate-qr.png` is declared in prompt 19 (F12). Prompt 01 runs on sonnet low (F13).

**Non-goals:** everything in §1 "Non-goals for v1" and "After v1"; connecting Vercel (the user's step); tests for DOM modules (`main.js`, `editor.js`), which are verified by syntax check and manual run; any runtime dependency.
